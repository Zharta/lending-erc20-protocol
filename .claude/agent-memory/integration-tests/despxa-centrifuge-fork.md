**Deposit fulfilment recipe (impersonate SPOKE, call manager.callback directly — bypasses spoke.requestCallback):**
`manager.callback(poolId, scId, assetId, payload, sender=SPOKE)` three times, in order:
1. ApprovedDeposits:  `payload = bytes([1]) + assetAmount(uint128 BE 16B) + pricePoolPerAsset(uint128 BE 16B)`  (use price = 1e18 D18-one)
2. IssuedShares:      `payload = bytes([2]) + shareAmount(16B) + pricePoolPerShare(16B)`  (shareAmount = the deJAAA to mint; `balanceSheet.issue` MINTS them into escrow, no pre-funding needed)
3. FulfilledDepositRequest: `payload = bytes([4]) + investor(bytes32) + fulfilledAssets(16B) + fulfilledShares(16B) + cancelledAssets(16B)`
   - investor bytes32 is LEFT-aligned: `address_bytes(20) + zeros(12)` (mgr uses `CastLib.toAddress` = `address(bytes20(x))`, requires bottom uint96 == 0). Getting this wrong -> `PrefixNotZero` (0xe8bd1659).
RequestCallbackType enum: Invalid=0, ApprovedDeposits=1, IssuedShares=2, RevokedShares=3, FulfilledDepositRequest=4, FulfilledRedeemRequest=5. Encoding is `RequestCallbackMessageLib` (protocol-v3 src/vaults/libraries/RequestCallbackMessageLib.sol), abi.encodePacked.

**Claiming the deposit:** the despxa vault's `claim_mint` calls `AsyncVault.deposit(claimableDepositRequest, self, self)`. MUST pass the EXACT `claimableDepositRequest(0, controller)` amount (== `maxDeposit`), NOT the originally requested assets — claiming more reverts `ExceedsMaxDeposit` (0xe4bac01b) because fulfilledShares/depositPrice rounds maxDeposit down by ~1 wei. After 1000e6 USDC deposit fulfilled at 0.974e18 shares, `claimableDepositRequest` = 999999999 and the claim returns ~0.974e18 deJAAA. So in start_loan the minted collateral is slightly less than mint_spend*price — read it as ground truth from `dej.balanceOf(loan_vault)` after start_loan (like the acred test reads minted collateral).

**Redeem fulfilment (VALIDATED on fork):** two callbacks impersonating SPOKE:
1. RevokedShares (type 3): `bytes([3]) + assetAmount(16B) + shareAmount(16B) + pricePoolPerShare(16B)` — burns the shares, notes the asset (USDC) withdraw. Use assetAmount = the USDC to pay out (e.g. `vault.convertToAssets(redeemed_shares)`), shareAmount = redeemed_shares, price = 1e18.
2. FulfilledRedeemRequest (type 5): `bytes([5]) + investor(bytes32 LEFT-aligned) + fulfilledAssets(16B) + fulfilledShares(16B) + cancelledShares(16B)`.
Then the despxa vault's `claim_redeem` calls `AsyncVault.redeem(claimableRedeemRequest, self, self)` and USDC lands in the loan vault; `settle_loan(loan, EMPTY_SIGNED_REDEEM_RESULT)` distributes. No pre-funding of USDC needed — `balanceSheet` pays from the pool escrow. Full lifecycle create->fulfil deposit->start->redeem->fulfil redeem->settle passes; lender gets exactly principal+interest, surplus to borrower.

**CANCEL IS SYNCHRONOUS on the real manager — THE key deviation from AsyncVaultMock.** `AsyncRequestManager.cancelDepositRequest` (and cancelRedeemRequest) processes IMMEDIATELY: right after the vault submits the cancel, `claimableCancelDepositRequest == full amount` and `pendingCancelDeposit == False` (mgr.investments tuple: idx4 pendingDeposit->0, idx6 claimableCancelDeposit->full, idx8 pendingCancelDeposit->False). The mock instead needs a separate `process_cancel_deposit` hook. Consequence for tests: `cancel_pending_loan` phase 1 (`request_pending > 0` branch) returns False AND makes the cancel claimable in the SAME tx; the NEXT `cancel_pending_loan` call hits the `cancel_claimable > 0` branch and completes (returns True) with NO impersonated cancel-fulfil step in between. So flows 2 (cancel pending) and 5 (cancel redeem) need only two back-to-back `cancel_*` calls, not an issuer step. investments tuple order: (maxMint, maxWithdraw, depositPrice, redeemPrice, pendingDeposit[4], pendingRedeem[5], claimableCancelDeposit[6], claimableCancelRedeem[7], pendingCancelDeposit[8], pendingCancelRedeem[9]).

**boa gotcha:** boa's `BoaError.__str__` / call_trace formatter crashes ("<exception str() failed>") on these Centrifuge reverts. To read a revert reason use `comp = boa.env.execute_code(to_address=..., sender=..., data=selector+args); comp.is_error; comp.output` then decode `output[:4]` as a 4-byte error selector against protocol-v3 `src/**/*.sol` `error` defs. Custom-error registry lives in /tmp/protocol (git clone github.com/centrifuge/protocol, tag near 2026-06-03). Manager ABI fetched from Etherscan v2 (chainid=1 getabi) — its fulfil path is `callback(uint64,bytes16,uint128,bytes)` + `trustedCall`, NOT any `fulfill*` external fn.
